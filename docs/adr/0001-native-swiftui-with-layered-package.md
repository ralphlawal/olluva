# ADR 0001: Native SwiftUI app with a layered local Swift package

Status: accepted · 2026-10-09

## Context
The product must be a real native iOS app with widgets, and must stay maintainable as it grows. The brief asks for clear separation between UI, domain rules, data access, widget sharing, notifications and entitlements.

## Decision
- Swift + SwiftUI, minimum iOS 17 (Observation, interactive WidgetKit APIs, StoreKit 2 views, `MagnifyGesture`).
- Everything that is not screen code lives in a local package, `Packages/CoupleKit`, split into targets whose dependencies only point one way:

  `CoupleDomain` ← `CoupleDesign` ← `CoupleWidgetUI`; `CoupleDomain` ← `CoupleLocalBackend`; `CoupleDomain` ← `CoupleSupabase`

- Feature code depends on repository **protocols** in `CoupleDomain`. Only `CoupleSupabase` imports the Supabase SDK.
- State is held in `@Observable` stores on the main actor, created once by `AppEnvironment` (the composition root).
- The Xcode project is generated by XcodeGen from `project.yml` and is not committed.

## Consequences
- Domain rules and the in-memory backend build and test on macOS with `swift test` in under a second, with no simulator.
- The widget extension can link the note renderer without linking the app or the Supabase SDK.
- Swift language mode is 5 (the compiler is 6.3). Moving to Swift 6 strict concurrency is a known follow-up, not done here.
- One third-party dependency: `supabase-swift`.
